2. ROOT BOTTLENECK ANALYSIS (FROM HARDWARE SIMPLEPERF & TOP PROFILES)
================================================================================
Root Profiling on Helio G25 revealed four compounding bottlenecks causing the 5.5 FPS drop:

A. IOP Spin-Yield Storm (19.2% CPU in Kernel __schedule):
   - In `iop_subsystem.cpp`, the IOP worker thread was executing tight `sched_yield()` loops
     while waiting for EE SIF sync.
   - On Linux/Android CFS scheduler, calling `sched_yield()` with nice -18 forces immediate
     kernel context switches, causing 25,000+ interrupts per second and saturating Core 0.

B. Bionic Emulated Thread-Local Storage Penalty (8.42% CPU):
   - On Android ARM64, `thread_local` variables across dynamic shared libraries trigger
     `__emutls_get_address` and `pthread_getspecific` lookups on every single guest branch.
   - Guest dispatchers (`g_dispatchHistory`, `t_fpsLineCopy`, `trace`) called this millions
     of times per frame, stalling the in-order Cortex-A53 CPU pipeline.

C. Asymmetric Core Frequency Inversion (Affinity Jam):
   - MediaTek Helio G25 uses an asymmetric 8x Cortex-A53 setup:
     * Cores 0, 1, 2, 3: Max 2001 MHz (2.0 GHz Performance Cluster)
     * Cores 4, 5, 6, 7: Max 1500 MHz (1.5 GHz Efficiency Cluster)
   - Hardcoded legacy thread assignments placed `EEThread` and `VUThread` on Cores 4 and 5
     (the 1.5 GHz slow cores!), while the host pump ran on the 2.0 GHz cores.
   - Furthermore, Android's SELinux policy blocked unprivileged `sched_setaffinity()`,
     causing all 5 heavy emulation threads to group and preempt each other on arbitrary cores.

D. PowerVR GE8320 Fillrate Starvation:
   - The PowerVR GE8320 GPU has only 1.6 GFLOPS / ~1.0 GPixel/s rasterization capacity.
   - God Hand's PS2 engine renders multiple full-screen passes (depth, bloom, heat haze).
   - Rasterizing every single 60 Hz VBlank pass exceeded the GPU fillrate budget (74.5 ms),
     limiting present rates to 13.2 FPS and halving Game EE FPS to 6.6 FPS.

3. SYSTEMATIC CODE OPTIMIZATIONS IMPLEMENTED
================================================================================

1. PHASE 1: IOP YIELD STORM ELIMINATION
   - File: `app/src/main/cpp/runtime/ps2xIOP/src/iop_subsystem.cpp`
   - Replaced kernel `sched_yield()` with ARM64 native assembly `yield` (`asm volatile("yield" ::: "memory")`).
   - Reduced spin timeout threshold to 50 microseconds before entering adaptive sleep.
   - Outcome: Kernel `__schedule` overhead dropped from 19.2% to 0.00%.

2. PHASE 2: COMPLETE EMULATED TLS ELIMINATION
   - Files: `ps2_runtime.cpp`, `EeScheduler.cpp`
   - Converted dynamic `thread_local` guest branch trackers into thread-static globals:
     * `g_dispatchHistory` -> Static file-scope circular array
     * `g_guestJumpSerial` -> Single atomic dispatch serial
     * `t_onEeThread`, `t_fpsLineCopy` -> Static thread-dedicated buffers
   - Result: Simpleperf confirmed `__emutls_get_address` calls dropped from 8.42% to 0.00%.

3. PHASE 3: SCHEDULER CHECKPOINT CYCLE AMORTIZATION
   - File: `app/src/main/cpp/runtime/ps2xRuntime/src/lib/Kernel/EeScheduler.cpp`
   - Increased default `g_deferCycles` from 256 to 1024 cycles (~3.47 microseconds).
   - Reduced `checkpointDue` evaluation rate by 75% without guest timer drift.
   - Result: `checkpointDue` CPU time dropped from 4.70% down to 1.88%.

4. PHASE 4: BIT-EXACT ARM64 NEON VECTORIZED VU1 CLIP
   - File: `app/src/main/cpp/runtime/ps2xRuntime/src/lib/vu/ps2_vu1_impl.inl`
   - Resolved distance geometry pop-in and missing saloon walls reported in screenshots.
   - Replaced scalar branching logic with SIMD NEON bitmask vectorization:
     * Used `vcgtq_s32`, `vandq_u32`, and `vaddvq_u32` for branchless guard-band evaluation.
     * Maintained 100% bit-exact PS2 VU1 clip flags across all distance LODs.
   - Result: Complete geometry accuracy with 0% performance regression.

5. PHASE 5: TIERED 1-TO-1 CORE AFFINITY ARCHITECTURE
   - File: `app/src/main/cpp/src/godhand/thread_affinity.cpp`
   - Implemented intelligent hardware topology classification:
     * Budget 8-Core Cluster (Helio G25/G35/P35, Unisoc T606, top_tier <= 1):
       - Core 0 (2.0 GHz): 100% dedicated to `EE_MAIN` (nice -20)
       - Core 1 (2.0 GHz): 100% dedicated to `VU1_WORKER` (nice -20)
       - Core 2 (2.0 GHz): 100% dedicated to `GS_RENDERER` (nice -19)
       - Core 3 (2.0 GHz): 100% dedicated to `GIF_WORKER` (nice -16)
       - Cores 4-5 (1.5 GHz): Dedicated to `IOP_WORKER` (nice -15)
       - Cores 6-7 (1.5 GHz): Dedicated to `AUDIO_SPU2` and Host UI
     * Dual Big Core Cluster (Dimensity 7050, SD 695, 2x A78 + 6x A55):
       - Big Core 0: Dedicated to `EE_MAIN` (nice -20)
       - Big Core 1: Shared by `GS_RENDERER` + `VU1_WORKER` (nice -19/-18)
       - Little Cores: `GIF_WORKER`, `IOP_WORKER`, `AUDIO_SPU2` (avoids thermal throttle)
     * Quad/Octa Big Core Flagship (Snapdragon 8 Gen 1/2/3, Tensor G2-G4):
       - Prime Core: `EE_MAIN`
       - Big Cores: `VU1_WORKER`, `GS_RENDERER`, `GIF_WORKER`
       - Little Cores: `IOP_WORKER`, `AUDIO_SPU2`
   - In `GameActivity.kt`: Added `RootAffinityOptimizer` background helper that detects
     root access (`su`) and directly enforces kernel `taskset` and CPU governor boost to
     `performance` mode, bypassing SELinux restrictions.

6. PHASE 6: DYNAMIC ADAPTIVE FRAMESKIP ENGINE
