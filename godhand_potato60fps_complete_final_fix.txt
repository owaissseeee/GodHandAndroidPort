1. WHY AUDIO & CLOVER INTRO BUFFERED (EVEN AT 60 FPS ON FLAGSHIP):
   - Cause A (Halved IOP Clock in `EeScheduler::accountCycles`):
     In Commit 2285c87e, changing `g_iopStash += elapsed` to `g_iopStash += (elapsed >> 1)`
     cut the PS2 IOP & SPU2 hardware clock to 50% speed! Because the SPU2 generates
     48,000 Hz audio driven directly by `advanceIopEeCycles()`, feeding it half the
     cycles caused it to generate only 24,000 samples/sec while Android's AAudio
     drained 48,000 samples/sec (50% audio starvation!), and ran the Clover Intro
     CDVD/ADX streamer at 0.5x speed!
   - Cause B (256-Frame = 5.3ms Audio Buffer in `jni_bridge.cpp` + Dropped Re-Anchor Time):

     milliseconds were never fed to `advanceIopEeCycles()` (as noted in the comment
     on line 2720: "emulated time lost for good: the SPU2 makes that much less audio").

```cpp
uint64_t EeScheduler::skipIdleCycles() noexcept
{
    const GuestThread *running = currentThread();
    if (running == nullptr || m_insideInterrupt || !running->invocations.empty() ||
        hasReadyAtOrAbovePriority(running->currentPriority))
    {
        return 0u;
    }

    t_inIdleSkip = true;
    uint64_t skipped = 0u;
    while (!m_checkpointPending.load(std::memory_order_acquire) &&
           !m_rescheduleRequested &&
           m_pendingInvocations.empty())
    {
        const uint64_t nextEventCycle = m_nextDeadlineCycle.load(std::memory_order_acquire);
        if (nextEventCycle == 0u || m_eeCycle >= nextEventCycle)
        {
            break;
        }
        const uint64_t step = std::min({nextEventCycle - m_eeCycle,
                                        kIdleSkipStepCycles * 8u,
                                        m_runtime.memory().cyclesUntilNextEeTimerInterrupt()});
        if (step == 0u)
        {
            break;
        }
        accountCycles(static_cast<uint32_t>(step));
        skipped += step;
    }
    t_inIdleSkip = false;
    return skipped;
}
```
