## PART 1: EXACT ROOT-CAUSE DIAGNOSIS OF YOUR 3 NEW ISSUES & WHY A 294 MHz PS2 RUNS THIS EFFORTLESSLY

### 1. Why the Mid-Ranger Menu Got Stuck at 30 Main FPS / 30 Game EE FPS (And Why Both Phones Lost 2–4 FPS)
- **Root Cause A (`gs_pcsx2_backend.cpp` Step 10 VSync Skip)**:
  - In Phase 2 Step 10, we added an early `return;` inside `GSPcsx2Backend::VSync()` whenever `curGameFrames == s_lastPresentedGameFrame`.
  - Because God Hand's engine (`cSys`) updates at 30 Hz (`rdram[0x00747A09] = 0x02`, flipping once every 2 VBlanks) even on the Main Menu while the PS2 video output runs at 60 Hz, returning early from `GSPcsx2Backend::VSync()` on every 2nd VBlank **skipped `g_perfWindowPresents++` and skipped `g_api->vsync()` on every odd VBlank**, artificially locking the Mid-Ranger's Main Present FPS to **30 FPS** at the menu!
  - Worse, inside PCSX2's Vulkan backend (`Bridge.cpp`), `GSvsync()` also manages command-buffer ring retirement and texture cache age. Skipping `g_api->vsync()` completely on odd VBlanks stalled command buffer retirement until the next VBlank, causing bursty 2-frame stalls that **dropped 2–4 FPS** on both the Mid-Ranger and Redmi 10A!
  - **The Fix**: **Completely remove Step 10 from `gs_pcsx2_backend.cpp`**! Instead, enable PCSX2's native internal duplicate-frame skip (`options.SkipDuplicateFrames = true;` in `Bridge.cpp`), which keeps the 60 FPS VSync loop running at 60 Hz on menus while skipping redundant GPU render-target draws inside `GSRendererHW` when no new primitives were drawn.

- **Root Cause B (`EeScheduler.cpp` Step 9B Unconditional `skipIdleCycles()` in `func_0030B148`)**:
  - In God Hand, a single combat frame's rendering is split across **multiple GS `SIGNAL` interrupts** (`EE` kicks Part 1 -> `VUThread`/`GIFThread` hit a GS `SIGNAL` -> `EE` GS interrupt handler kicks Part 2 -> `GIFThread` hits `FINISH`).
  - When Step 9B called `skipIdleCycles()` inside `EeScheduler::checkpointDue` while `pc` was in `func_0030B148` (`0x0030B168..0x0030B298`), it jumped `m_eeCycle` forward by `4,915,298` cycles to the next VBlank **while `VUThread` and `GIFThread` were STILL busy processing Part 1 of the frame (`ps2x::asyncvif::pipelineBusy() == true`)**!
  - That caused VBlank to fire *before* `GIFThread` raised the GS `SIGNAL` interrupt for Part 1, making Part 2 miss the frame swap window and dropping 2–4 FPS!
  - **The Fix**: In `EeScheduler::checkpointDue`, when `pc` is inside `func_0030B148`'s wait loop (`0x0030B168..0x0030B298`):
    1. If `gsInterruptUnseen()` is true: immediately unwind (`m_checkpointPending = true; m_unwinding = true; return true;`) so the EE dispatches the GS `SIGNAL`/`FINISH` interrupt in **0 microseconds**!
    2. If `ps2x::asyncvif::pipelineBusy(m_runtime.memory())` is true (`VUThread` or `GIFThread` is still working on the frame): call `ps2x::asyncvif::waitPipelineIdle(m_runtime.memory(), std::chrono::microseconds(150))` **WITHOUT advancing `m_eeCycle`**! This stops `EEThread` from burning fake spin cycles while waiting for `VUThread`/`GIFThread` and prevents VBlank from firing before the frame's drawing finishes!
    3. **ONLY** when `!ps2x::asyncvif::pipelineBusy(m_runtime.memory()) && !gsInterruptUnseen()` (meaning `VUThread` and `GIFThread` have 100% finished the frame, and the ONLY thing `func_0030B148` is waiting for is the VBlank tick counter): call `skipIdleCycles()` to jump cleanly to VBlank!

### 2. Why the Ground Sometimes Had an Invisible Graphical Glitch
- **Root Cause (`ps2_vu1_impl.inl` `PS2X_VU1_SKIP_CLAMP=1` & `writeVf` Overwriting `rawReg`)**:
  1. On the real PS2 VU1 hardware, there are **no IEEE-754 `NaN`s or `Inf`s**—exponent `0xFF` (`0x7F800000..0x7FFFFFFF`) is treated as a normal finite float (`1.7e38..3.4e38`). God Hand's stage/ground VU1 shaders load integer/GIFtag/ADC masks (which have exponent `0xFF` = IEEE `NaN`) into `vf` registers. When `PS2X_VU1_SKIP_CLAMP=1` bypassed `vnorm()`, multiplying a `NaN` bit pattern by `0.0f` produced `NaN`, poisoning vertex coordinates (`X, Y, Z, W = NaN`) and making ground mesh strips vanish!
  2. In Phase 2 Step 11C, `writeVf()` wrote `normalized` into `rawReg(vu, reg)` (`vu.m_state.vf[reg]`). Because `LQ` loads raw GIFtag/ADC integer bits (exponent `0` = IEEE denormals) into `vf` registers and `SQ` writes `rawReg(vu, reg)` out to the XGKICK packet buffer, overwriting `rawReg` with `normalized` zeroed out the GIFtag/ADC bits!
- **The Fix**:
  1. Restore `writeVf()` so `rawReg(vu, reg)` **always** stores `raw` (`storeDest(rawReg(vu, reg), raw, dest)`) while `ctx.norm[reg]` stores `normalized`.
  2. Never disable `vnorm()`. Instead, replace the slow 9-instruction `vnorm()` with a **3-instruction branchless ARM64 NEON unsigned-min magnitude clamp (`vminq_u32(mag, 0x7F7FFFFFu)`)** + hardware `FPCR.FZ` (Flush-to-Zero). Since `0x7F7FFFFFu` is the exact bit pattern right below `0x7F800000u` (`Inf`/`NaN`), `vminq_u32(mag, 0x7F7FFFFFu)` clamps all `Inf`/`NaN` bit patterns to `MAX_FLOAT` in **1 instruction** while leaving every normal float 100% untouched!

```cpp
                // 3. VUThread and GIFThread are 100% IDLE (frame drawing is completely finished!).
                //    Now it is 100% safe to fast-forward the remaining idle EE cycles to the VBlank boundary!
                skipIdleCycles();
                if (m_checkpointPending.load(std::memory_order_acquire))
                {
                    m_unwinding = true;
                    g_deferUntil = 0u;
                    g_ps2xEeDeferBudget.store(0u, std::memory_order_relaxed);
                    return true;
                }
            }
        }
    }
#endif
```
Look at why this works on **both** the Mid-Ranger and the Redmi 10A:
- While `VUThread` and `GIFThread` are rendering the frame (`pipelineBusy() == true`), `EEThread` sleeps in 150 µs increments (`waitPipelineIdle`) **without advancing `m_eeCycle`**, freeing CPU power/bandwidth for `VUThread`/`GSThread` and never triggering VBlank prematurely!
- The microsecond `GIFThread` raises a GS `SIGNAL` or `FINISH` interrupt (`gsInterruptUnseen()`), `EEThread` unwinds immediately and kicks the next DMA chain!
- Once `VUThread` and `GIFThread` finish the frame (`!pipelineBusy()`), `skipIdleCycles()` jumps straight to the next VBlank boundary in 0 cycles instead of spinning in `func_0030B148`!

```cpp
static std::vector<CpuCoreInfo> detectSortedCores() {
    std::vector<CpuCoreInfo> cores;

    long conf_cpus = sysconf(_SC_NPROCESSORS_CONF);
    int total_cpus = (conf_cpus > 0 && conf_cpus <= 64) ? static_cast<int>(conf_cpus) : 8;
    for (int probe = total_cpus; probe < 8; ++probe) {
        std::ifstream f("/sys/devices/system/cpu/cpu" + std::to_string(probe) + "/cpufreq/cpuinfo_max_freq");

        }
    }
```
